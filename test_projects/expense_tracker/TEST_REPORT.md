# HarnessAgent 真实代码增改测试报告

## 测试目标

测试项目最初包含记账模型、JSON 存储、业务服务、CLI 和 8 项通过的测试。真实 Agent 的任务是新增月度 Markdown 报告、`report` 子命令、服务与 CLI 测试以及 README 示例。

## 真实运行结果

| 轮次 | 结果 | 主要表现 |
|---|---|---|
| 第一次 | 20 次迭代后达到上限 | 新增服务方法、CLI 入口和服务测试；两次 Patch 上下文不匹配被安全拒绝；没有完成 README、CLI 测试和最终验证 |
| 第二次 | 20 次迭代后达到上限 | 补充 CLI 测试和 README，并真实运行验证；验证发现 2 项文案断言失败，但修正前耗尽迭代 |
| 第三次 | 14 次迭代后等待审批 | 多次 Patch 失败后请求用 `run_shell` 字符串替换源码，并加入未要求的排名占比；该请求与用户限制冲突，因此未批准 |

三次会话都没有绕过权限或验证门禁。第三次等待中的 Shell 没有执行，也没有修改文件。

## 最终状态

根据原始需求手工清理多余排名并修正文案与断言后：

```text
12 passed
```

CLI 已实际验证 `add` 和 `report`，金额继续使用 `Decimal`，报告标题、分类汇总和精确总计均符合要求。

## 暴露出的 HarnessAgent 问题

- 多文件任务中过于频繁地读取文件和更新计划，浪费迭代与真实 API 时间；
- Patch 上下文不匹配后，模型缺少高效的局部重试策略；
- 模型会编写符合自己实现的测试，而不是始终坚持用户原始文案；
- 接近迭代上限时没有优先完成测试和最终验证；
- Patch 多次失败后会退回到需要审批的 Shell 修改，且可能顺带加入未要求功能。
